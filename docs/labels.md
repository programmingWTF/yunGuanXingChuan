# Issue / PR 标签规范

> 标签体系模仿 NUAAMap 项目设计，用于对 Issue 和 Pull Request 进行分类、评估和管理。
> 本仓库由计算机小组维护，不使用"小组"标签，改用「模块」标签标注改动范围。
>
> **标签由组长统一用 AI 添加**。团队成员提交 Issue / PR 时**不需要自己打标签**，把内容按模板写清楚即可。

---

## 规模（预估工作量）

| 标签 | 含义 |
|------|------|
| `规模：XS` | 极简改动，预计几分钟 |
| `规模：S` | 小改动，预计半天内 |
| `规模：M` | 中等改动，预计 1-3 天 |
| `规模：L` | 大改动，预计 3-7 天 |
| `规模：XL` | 超大改动，预计超过 1 周 |

## 优先级

| 标签 | 含义 |
|------|------|
| `优先级：P0` | 🚨 紧急：安全漏洞、崩溃、核心功能不可用 |
| `优先级：P1` | 🔴 高：用户可见 Bug、功能回归 |
| `优先级：P2` | 🟡 中：常规任务 |
| `优先级：P3` | ⚪ 低：优化、文档、锦上添花 |

> ⚠️ P0 别滥用——每件事都是"紧急"就等于没有紧急。

## 段位（Issue / PR 质量评级）

用王者荣耀段位评估 Issue 和 PR 的质量，从低到高：

| 标签 | 含义 |
|------|------|
| `段位：未定级` | ❓ 信息不足，尚无法评估 |
| `段位：倔强青铜` | 🥉 初具雏形，仍需补充大量信息 |
| `段位：秩序白银` | 🥈 基本清晰，可以正常处理 |
| `段位：荣耀黄金` | 🥇 描述完整，质量不错 |
| `段位：永恒钻石` | 💎 高质量，细节到位 |
| `段位：至尊星耀` | 🌟 非常出色，堪称范例 |
| `段位：最强王者` | 👑 顶级质量，完美无瑕 |

**评定标准**：
- **Issue 质量**：标题清晰度、复现步骤、截图/日志、环境信息
- **PR 完成度**：改动合理性、代码质量、是否附说明、改动范围是否聚焦

## 类型

| 标签 | 含义 |
|------|------|
| `类型：Bug` | 功能异常，需要修复 |
| `类型：功能请求` | 新功能或改进建议 |
| `类型：文档` | 文档改进或补充 |
| `类型：数据` | 数据、语料、受众画像相关 |
| `类型：问题咨询` | 需要讨论或答疑 |
| `类型：重构` | 重构代码，行为不变 |

## 模块（改动范围，替代"小组"）

| 标签 | 含义 |
|------|------|
| `模块：智能体` | 智能体 Agent（`src/agents/`） |
| `模块：议会辩论` | 议会辩论引擎（`src/parliament/`） |
| `模块：流程编排` | 流程编排（`src/pipeline.py`） |
| `模块：校验层` | 校验层（`src/verification/`） |
| `模块：知识图谱` | 知识图谱 / 向量库 / 数据（`src/knowledge/`、`data/`） |
| `模块：后端API` | 后端接口（`api/`） |
| `模块：前端` | 前端界面（`frontend/`） |
| `模块：部署` | 部署、Docker、脚本（`scripts/`、`docker-compose.yml`） |

## 状态

| 标签 | 含义 |
|------|------|
| `状态：需要更多信息` | 等待作者补充信息 |
| `状态：等待确认` | 等待维护者确认 |
| `状态：已确认` | 问题已被确认存在 |
| `状态：进行中` | 正在处理中 |
| `状态：等待审核` | PR 等待审核 |
| `状态：准备合并` | PR 可以合并 |

## 杂项

| 标签 | 含义 |
|------|------|
| `重复` | 此 Issue 或 PR 已存在 |
| `good first issue` | 适合新手练手（GitHub 内置） |
| `invalid` / `wontfix` / `help wanted` | GitHub 标准工作流标签（保留） |

## 使用说明

- **提交者不需要自己打标签**：提 Issue / 开 PR 时把内容按模板写清楚即可，**AI 维护机器人 LiGuiyu-AI 会自动为它们添加合适的标签**（详见 [bot-automation.md](bot-automation.md)）。上表就是 AI 打标签用的参考字典。
- **标签语义**：提交者阅读上表可了解各标签含义，方便用规范的语言描述问题（如指明涉及模块）。
- **状态标签**（`状态：*`）随任务推进由 Assignee / 维护者更新；「状态：已过时」由过时管理工作流自动标记。
- **段位标签**由机器人在 Review 后评定，作为质量反馈。
- 增删标签需要管理员权限；发现标签类别不够用，开 Issue 向组长提出。
