## 二、百炼的知识库（RAG）是什么

### 2.1 定位
阿里云百炼是"一站式大模型开发与应用平台"。除了模型调用（兼容 OpenAI 接口），它内置了 **知识库（RAG）** 能力：接入私有数据/文件 → 语义检索 → 供大模型回答。

> 官方定位："知识库支持对私有数据或文件进行**语义检索**，可找出语义相同或相近的内容，即使关键词匹配度极低甚至为零。"

### 2.2 工作原理
文件 → 解析 → **切片（chunk）** → 向量化（embedding）→ 存入向量库 → 检索时做**语义检索 + 排序模型重排序** → TopK 切片喂给大模型。

这和我们自研的 `src/knowledge/vector_store.py`（FAISS + text-embedding + 语义检索）**思路完全一致**，只是平台化托管。

### 2.3 关键限制（重要）
- **地域限制**：知识库功能**仅华北2（北京）地域**支持，其他地域（新加坡、法兰克福等）不支持。
- **计费**：独立于模型推理计费。
  - 知识库规格：**标准版 0.03 元/小时，旗舰版 0.2 元/小时**（按规格时长）
  - 叠加模型调用费（检索向量的 embedding、排序模型、对话生成）
  - **不支持节省计划或资源包等预付费抵扣**
- **创建后不可改**：① 知识库类型创建后不可更改；② **创建后无法更改切片方式（chunk）**；③ 向量模型/向量存储类型创建后不可改（视觉理解场景尤其如此）。

## 三、知识库支持的数据类型与自定义能力

### 3.1 知识库类型
创建时可选择（单一知识库不支持同时选多个）：
- **文档搜索**（检索非结构化数据）：再选使用场景——
  - **基础文档问答**：纯文本文档语义检索
  - **视觉理解（富文本文档）**：多模态向量模型对 PDF/图片做视觉级理解，保留版面，适用复杂排版/图表/公式
  - **极速问答**：面向 FAQ、产品参数表等，低延迟优化
- **数据查询**（结构化数据，Chatbot / NL2SQL）：FAQ、商品/人员信息查询
- 另有图片问答类、音视频搜索类（文档提及）

### 3.2 支持的文件格式
通过「数据连接」统一管理外部数据源：
- **文件连接器**：非结构化文档（**PDF、Word、Markdown 等**），本地上传或 OSS 导入
- **表格连接器**：结构化表格（**CSV、Excel/XLSX** 等）
- **数据连接器**：MySQL / PostgreSQL / PolarDB-X / 语雀 / OSS（实时访问）
- 解析方式可选：**电子文档解析**（最快，不含插图）、**文档智能解析**（OCR 插图+摘要）、**大模型文档解析**（千问 VL 理解插图图表）、**Qwen VL 解析**（纯图片）、**音视频解析**（语音转写+视频帧+剧情解析）

### 3.3 切片策略（可自定义，核心）
| 切片方式 | 说明 |
| --- | --- |
| **智能切分**（默认） | 系统内置，官方称"经评测对多数文件检索效果最佳"；按分句拆分成段落再合成切片 |
| **按长度切分** | 适合对 Token 数有严格要求的场景 |
| **按页切分** | 每页独立主题的文档 |
| **按标题切分** | 支持 `#`/`##` 标题层级，适合结构化长文档——**与我们的 Markdown 标题切分思路一致** |
| **按正则切分** | 自定义正则表达式（如按句号切分 `(?<=。)`） |
| **按符号切分** | 按选定的标点符号切分 |

**重叠字符数**：相邻切片重叠，建议设为**最大分段长度的 10%~25%**（必须小于分段长度）。

**切片标题**：自动按文档标题层级生成 `title`（最近一级标题）和 `hier_title`（完整路径，如 `一级标题|>二级标题`）。

**Meta 信息抽取（元数据）**：可为切片附加 key-value 元数据（常量 / 变量 file_name、cat_name / 大模型自动提取 / 正则提取 / 关键词搜索），显著提升检索准确率，也支持 `metadata_filter` 过滤。**这与我们 #37 预处理模块保留"来源文件、章节标题、日期、语言"元数据的设计目标一致。**

**多轮对话改写**：可将带上下文的问题改写为独立查询再检索（轻量模型实现）。

### 3.4 向量 / 排序 / 检索参数（平台内置）
- **向量模型**：`text-embedding-v4`（推荐，512 维）/ `text-embedding-v3`（512 维）/ 视觉理解自动用 `qwen3-vl-embedding`
- **排序模型**：`qwen3-rerank`（官方排序，综合语义+文本特征如 BM25）/ `qwen3-rerank(hybrid)`（推荐）
- **相似度阈值**：筛选召回切片（应用可覆盖知识库默认值）
- **最大召回数量**：上限 **20**（TopK）
- **向量存储**：内置向量库（免费，默认）或 **ADB-PG**（AnalyticDB for PostgreSQL，需开启向量引擎优化，可能产生费用）

### 3.5 API / 集成方式
- **零代码**：控制台创建知识库 → 关联智能体应用（配置相似度阈值、多知识库权重）或拖入工作流知识库节点
- **编程**：用 `alibabacloud_bailian20231229` SDK 或 REST API 操作知识库——
  - 流程：`ApplyFileUploadLease`（申请上传租约）→ 上传文件 → `AddFile`（指定 parser，如 `DASHSCOPE_DOCMIND`）→ `CreateIndex`（指定 structure_type/source_type/sink_type）→ `SubmitIndexJob` → **`Retrieve`**（检索）
  - 需要环境变量：`ALIBABA_CLOUD_ACCESS_KEY_ID/SECRET`、`WORKSPACE_ID`（业务空间 ID）
  - 也有 `metadata_filter` 等请求参数

## 四、与自研方案对比

### 4.1 自研现状（云观星传 `src/knowledge/vector_store.py`）
- **入库**：FAISS（`IndexFlatIP` 内积，L2 归一化 ≈ 余弦）+ 自研 slice（按字符 400/重叠 50）
- **向量**：`dashscope.aliyuncs.com` compatible-mode，模型 `qwen3.7-text-embedding`，默认 1024 维（自动检测）
- **检索**：`search()` + `verify_claim()`（阈值分级校验事实）
- **预处理**：issue #37 已完成 `preprocessor.py`（txt/md/pdf/docx 解析 + Markdown 标题/段落切片 + 元数据），CLI `ingest_docs.py`
- **数据源**：固定种子数据 `data/science/`、`data/media/`，现可上传用户文档

### 4.2 逐项对比

| 维度 | 百炼知识库（RAG） | 自研 FAISS + 预处理（#37） |
| --- | --- | --- |
| 开箱即用 | ✅ 控制台 + 零代码集成 | ❌ 需自建，代码维护 |
| 文档格式 | 更广（PDF/Word/MD + 图片/视频/音视频 + Excel/CSV + 数据库） | txt/md/pdf/docx（pdf 需 pypdf） |
| 切片自定义 | ✅ 按长度/页/标题/正则/符号 + 重叠 + Meta 抽取 | ✅ Markdown 标题/段落 + 重叠 + 元数据（逻辑自控） |
| 元数据 | ✅ Meta 抽取 + metadata_filter | ✅ 来源/标题/日期/语言 |
| 视觉/富文档 | ✅ 多模态向量（qwen3-vl） | ❌ 无（纯文本向量） |
| 排序模型（rerank） | ✅ 内置 qwen3-rerank(hybrid) | ❌ 无（仅 topK 相似度） |
| 向量维度/模型 | text-embedding-v4，**512 维** | qwen3.7-text-embedding，**1024 维** |
| 存储 | 平台内置 / ADB-PG | 本地 FAISS 文件（`data/kg/vectors.faiss`） |
| 计费 | 规格时长(0.03/0.2元时) + 模型调用，独立计费 | 仅模型调用（embedding），无平台规格费 |
| 数据主权 | 数据上传到阿里云（隐私声明不用训练，但离开本地） | 数据完全本地可控 |
| 可定制/调试 | 受限（创建后不可改切片/向量/类型） | ✅ 完全可控、可迭代 |
| 地域限制 | ❌ 仅华北2（北京） | ✅ 无 |
| 检索能力扩展 | 受平台约束（召回上限 20） | ✅ 自由（TopK 自定） |
| 与现有代码集成 | 需新增 SDK 依赖 + 改调用链 | ✅ 已集成（vector_store 已在用） |

### 4.3 关键差异点
1. **维度不一致**：百炼知识库两种向量都是 **512 维**；我们自研用 **1024 维**。若未来迁移，现有 FAISS 索引和检索逻辑要么重灌、要么双轨并存。
2. **"创建后不可改"**：百炼知识库一旦创建，**切片方式、知识库类型、向量模型/存储都不能改**；自研可随时调参。
3. **自有数据主权**：百炼要求数据上传阿里云（虽有隐私声明），对新闻案例/学术资料这类可能涉密的材料需评估合规。
4. **视觉/富文档是平台明显优势**：自研对图片、复杂图表、音视频无能为力，这是平台的强项。

## 五、结论与建议

### 5.1 结论
- 百炼**确有成熟、开箱即用的 RAG 知识库模块**，且**切片策略可自定义**（按标题/长度/页/正则/符号 + 重叠 + Meta 抽取），能力非常完整，在视觉富文档、rerank、多数据源连接上是自研的明显优势。
- 但**当前阶段不建议迁移**，理由：
  1. **已有自研链路且运行正常**（FAISS + embedding + 检索 + #37 预处理已就绪），迁移成本高、收益不明显；
  2. 百炼知识库**创建后不可改**关键配置，迭代不灵活；
  3. 数据需上传阿里云，存在合规/主权考量；
  4. 需要阿里云 AK、业务空间 ID 等额外授权配置，增加运维负担；
  5. 独立计费（规格时长 0.03/0.2 元/时 + 调用费），对当前项目是新增成本。

### 5.2 建议（推荐路径：**继续自研 + 补充增强**）
1. **维持自研 FAISS 方案作为主力**，继续使用已完成 #37 的预处理模块，让新闻同学通过 `ingest_docs.py` 上传案例与学术资料。
2. **借鉴百炼平台的成熟切片经验**，回头补强自研逻辑（低成本、高性价比）：
   - 重叠字符比例参照 **10%~25%**（我们当前固定 50，可参数化）；
   - 增加**按正则/按符号切分**选项（接近百炼自定义方式）；
   - 强化元数据 `metadata_filter` 式过滤（我们已有 source/section/date/language，可加检索过滤）。
3. **保留迁移通道**：若未来需要**视觉富文档（PDF 图表、图片）、多模态检索、rerank、大规模多源数据**，可评估将「检索层」切换/嫁接为百炼知识库（通过 SDK `Retrieve`），前端业务不变——这是低风险的渐进迁移路径。
4. **暂不引入**平台知识库的依赖与计费，除非出现明确的富文档/多源检索硬需求。

### 5.3 给组员的落地建议
- 新闻方向同学现在就能用 `python scripts/ingest_docs.py --preview` 先看切片效果，再入库。
- 若后续真有「大量带图 PDF / 图表型学术资料」检索需求，再单独立 issue 评估是否启用百炼知识库做并行通道（可用阿里云免费/低门槛额度先 POC 验证检索效果再决定）。
